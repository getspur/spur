SPUR TUI — Complete Multi-View Architecture

Aligned with the PRD. Two primary screens (Dashboard + Session Detail) with drill-down views for Issues and Cost.

Navigation Map

Dashboard (home — Esc always returns here)
│
├── Enter/1-9 ──→ Session Detail (ReAct trace + chat)
├── p ──────────→ Issue Queue (PM inbox — Phase 3)
├── c ──────────→ Cost Detail (analytics — Phase 2)
├── r ──────────→ Run Dialog (modal overlay)
└── ? ──────────→ Help (modal overlay)

Architecture Summary

Component Pattern

src/
  app.rs — View enum, routing
  action.rs — Action message bus
  tui.rs — Terminal + async events
  views/
    dashboard.rs
    session_detail.rs
    issue_queue.rs (Phase 3)
    cost_detail.rs (Phase 2)
  components/
    agents_tree.rs
    activity_log.rs
    input_bar.rs
    react_trace.rs
    status_bar.rs

Data Flow

Orchestrator
  ├─ event_tx ──→ TUI
  │  (SpurEvent broadcast)
  │
  ├─ user_input_rx ←── TUI
  │  (chat messages, commands)
  │
  └─ permission ←→ TUI
     (request + oneshot response)
