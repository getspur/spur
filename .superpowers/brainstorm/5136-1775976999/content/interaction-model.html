SPUR TUI — Interaction Model

The TUI is an interactive orchestration interface, not just a dashboard. Users can chat with the brain and respond to permission requests.

Three Modes (vim-inspired)

Normal Mode (default)

Read-only monitoring. Navigate with vim keys. No input bar visible.

j/k scroll   Tab panels   / filter   ? help

Insert Mode (press i)

Chat with the brain agent. Input bar appears at bottom. Send with Enter.

Enter send   Esc cancel   !prefix interrupt

Command Mode (press :)

Spur commands. :kill, :cost, :filter, etc.

Enter execute   Esc cancel   Tab autocomplete

Insert Mode — Chat with Brain

Insert mode — user pressed i, typing a message
┌─ Agents ──────────────────────────────────────────────────────┐ ⠋ kiro BRAIN working 5m 10s $1.15 └─ ⠋ claude WORKER working 1m 30s $0.20 ├─ Activity ────────────────────────────────────────────────────┤ 10:35:01 [brain:kiro] → Delegating to claude: add tests 10:35:05 [worker:claude] Tool: read — tests/auth_test.rs 10:35:08 [worker:claude] Tool: write — tests/auth_test.rs 10:35:12 [worker:claude] ▸ ...writing integration tests for the token refr ├──────────────────────────────────────────────────────────────┤ > skip the integration tests, focus on unit tests only█ └──────────────────────────────────────────────────────────────┘ [Enter]send [Esc]cancel [!]interrupt+send $1.35 SPUR

Send behavior: Enter queues the message (sent after the brain's current turn completes). Prefix with ! to interrupt: cancels the current turn and sends immediately.

After Sending — Message in Log

Message sent, back to Normal mode

Permission Request — Inline Approval

Brain requests permission to delete a file
├─ Activity ────────────────────────────────────────────────────┤ 10:36:01 [brain:kiro] Tool: bash — cargo test 10:36:05 [brain:kiro] ✓ All tests passing 10:36:06 [brain:kiro] Tool: delete — src/old_auth.rs ⚠ Permission: delete src/old_auth.rs [y]es [n]o [a]ll ▼ following

Permission keys: y = approve once, n = deny, a = approve all similar. Auto-approves after 30s timeout (for unattended runs). In headless mode (spur run --background), auto-approves immediately.

Data Flow

Orchestrator TUI │ │ ├──── event_tx (broadcast) ────────────────►│ SpurEvent stream │ │ (agents, log, cost) │ │ │◄─── user_input_tx (mpsc) ────────────────┤ User messages │ │ (chat, commands) │ │ ├──── permission_tx (mpsc) ───────────────►│ Permission requests │◄─── permission_rx (oneshot per req) ────┤ User approval/denial │ │

Three channels: events (orchestrator→TUI), user input (TUI→orchestrator), permissions (bidirectional with oneshot per request).
