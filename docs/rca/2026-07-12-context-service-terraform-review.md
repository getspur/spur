# Terraform Review — `infra/spur-context-service/`

## (a) Executive Summary

The stack is structurally solid for its size — remote S3 state with DynamoDB locking and encryption, RDS-managed master credentials in Secrets Manager, mostly-scoped IAM, NAT-free VPC endpoint architecture, and a coherent Lambda-fast-path → ECS-fallback state machine. However, the **actually-deployed "default" environment directly contradicts the documented security posture**: `env/default.tfvars` sets `api_authorization_type = "NONE"` and `allow_anonymous_mutations = true` while the README claims the public route uses `AWS_IAM`, and the live Aurora catalog runs with `deletion_protection = false` combined with `skip_final_snapshot = true`. `terraform.tfvars` is tracked in git (contradicting both the README and the `.example` guidance) though it contains no secrets — only sizing/throttle config and a real account-ID ECR URI. Operationally, `deploy.sh` applies with `-auto-approve` and no plan gate, mutates ECR out-of-band, and a latent bug (`provisioned_concurrency` on `$LATEST`) will fail any apply that follows the committed example. Overall risk: **moderate-high**, dominated by the live env's authn posture and data-loss configuration rather than by code quality.

## (d) Rust-client ↔ Infra Consistency Notes

Evidence: direct reads of `crates/spur-core/src/mcp/context_service.rs` (lines 10–116: client construction, request path, auth, error envelope; tests at 450–518 confirming header behavior), `crates/spur-acp/src/config/mod.rs:443-462` (`ContextServiceConfig`), `crates/spur-context-service/src/mcp.rs:1409-1523` (`should_prefetch_source` / StartExecution input), plus `crates/spur-context-service/docs/ARCHITECTURE.md`. (Graph MCP tools were unavailable in this session — see note at top.)

1. **Endpoint shape — matches.** Client `POST`s `{"tool": name, "args": …}` to the bare base URL (`context_service.rs:72-75`); infra exposes an HTTP API with a `$default` catch-all route → `AWS_PROXY` payload v2.0 (main.tf:259-272), so any method/path lands on the Lambda. ✅
2. **Auth — matches the deployed env, contradicts the Terraform default.** Client supports only optional `Authorization: Bearer` (`context_service.rs:76-78`, tests 481-484/517) and **cannot SigV4-sign**; config comment says "production has no authorizer" (`config/mod.rs:452`). That only works because the live env overrides `api_authorization_type` to `NONE` — the module's "secure default" `AWS_IAM` and the `SpurContextServiceInvoke` policy are unusable by this client. Bearer tokens are currently transmitted but no API-GW authorizer exists to validate them (JWT/CUSTOM never configured) — consistent with the pending Cognito design spec. ⚠️ (Finding C2/M8.)
3. **Endpoint URL — drift.** Built-in default `https://zd3c3186v6.execute-api.ap-southeast-5.amazonaws.com` (`config/mod.rs:459`, asserted in `spur-cli/tests/init_ux.rs:410`) vs the runtime `[context_service]` URL `https://n1sbuuxt9k.execute-api.ap-southeast-5.amazonaws.com`. Two distinct API IDs, same region; one is stale — likely an API recreate rotated the URL (no custom domain in Terraform). ⚠️ (M8.)
4. **Timeouts — borderline.** Client 30s (`context_service.rs:10`) == serving Lambda 30s (`variables.tf:123`) == HTTP API's 30s integration cap. (L4.)
5. **Error contract — matches.** Client maps `{"error":{code,message}}` envelopes (`context_service.rs:111-116`); non-2xx handled.
6. **Tool surface — matches.** The 8 client tools (`external_catalog` … `external_index_status`) correspond to the service's MCP dispatch, and abuse-control env vars in `main.tf:197-215` line up with the `external_index` limits the README describes.
7. **State-machine input contract — verified.** ASL's `RouteSource` Choice requires `$.prefetch_source`; the service always includes it in StartExecution input (`spur-context-service/src/mcp.rs:1514-1523`). ✅
