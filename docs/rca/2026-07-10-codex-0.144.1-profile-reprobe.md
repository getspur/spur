**Date:** 2026-07-10

**Scope:** `@agentclientprotocol/codex-acp@1.1.2`, primary profile activation,

## Result

The final opt-in probe passed against adapter `1.1.2` and the actually executed
`codex-cli 0.144.1`. The `codex-0.144.1` evidence label is therefore valid. The
probe emits `codex-actual-<version>` for any other executed CLI version.

- The primary response contained the token authored only in the selected profile body.
- The parent rollout invoked `multi_agent_v1.spawn_agent` with
  `agent_type="spur-profile-probe-child"`.
- The spawn output identified one child thread; that thread's `session_meta` bound
  `agent_role="spur-profile-probe-child"` back to the exact parent.
- The raw ACP wait-state result for that bound child contained the token authored only
  in the generated `.codex/agents/spur-profile-probe-child.toml`.
- Both profile-probe clients advertised `{}` capabilities. They made zero filesystem,
  terminal, permission, or other agent-to-client requests; the restricted handler would
  deny any such request instead of auto-approving it.
- Positive activity was exactly `spawnAgent + wait` on ACP and
  `spawn_agent + wait_agent` in the controlled rollouts. The child made zero function
  calls, the negative control made none, and neither canary appeared in spawn arguments.
  Every rollout response-item type was also checked: positive allowed only passive
  messages/reasoning/outputs plus Codex's internal deferred-tool catalog search, while
  child and negative rollouts contained only messages/reasoning. Malformed, unreadable,
  missing, or unknown rollout evidence fails closed.
- Both controls used isolated, cleared `APP_SERVER_LOGS` directories. Adapter stderr
  and both `app-server.log` files contained zero
  `Ignoring malformed agent role definition` warnings.
- The completed token-bearing artifact tree contained 27 directories and 46 files. Every
  directory was `0700` and every file was `0600`, and private writers reject symlink
  targets; inherited `DEFAULT_AUTH_REQUEST`,
  `CODEX_API_KEY`, and `OPENAI_API_KEY` values were removed before launch.
- Each control was initialized as its own Git root. The no-profile control therefore
  inherited no project role files and returned exactly `NO_PROFILE_ACTIVE` without
  spawning a child or repeating either token.

No authentication or network blocker occurred during the focused live probe, so no
blocked signal was emitted.

## Automated test evidence

The review-gap regressions were run red before implementation:

- Restricted-mode tests failed because the profile client still advertised
  `fs/readTextFile` and terminal support, used the general absolute-path/subprocess
  handlers, and auto-selected allow options for permission requests.
- Activity-verdict tests failed because evidence retained neither server requests nor
  complete ACP/rollout function activity. A positive result could therefore survive an
  unexpected file/terminal tool or a canary copied into `spawn_agent` arguments.
- Mode tests observed generated profile/role/raw/stdout/stderr artifacts at `0644` and
  directories at `0755`, rather than the required `0600` and `0700`.
- Review-followup tests proved non-`function_call` child/negative actions and malformed
  or unreadable rollout JSONL were omitted from the first verdict. Symlink fixtures also
  proved private writers could truncate an external target, and the general Node probe
  source proved it removed environment-based authentication outside focused profile mode.
- App-server-log tests failed because the probe had neither an isolated log target nor
  an app-server warning scanner.
- Exact-role tests failed because no rollout/session binding existed. The prior
  synthetic ACP fixture intentionally omitted `agent_type` and still accepted every
  wait-state message after any `spawnAgent` update.
- The real Node version fixture set `CODEX_PATH` to a CLI reporting `9.9.9`, but version
  discovery incorrectly executed npm's bundled `0.144.1` CLI.
- The workspace-isolation test failed before controls became independent Git roots.
- Earlier seed/onboarding tests failed against the deprecated
  `@zed-industries/codex-acp` defaults before the N-1 implementation updated them.

## Source-only inference

These points informed the probe but are not presented as live proof:

- The adapter `1.1.2` manifest declares `@openai/codex` with range `^0.144.0`.
  That range cannot establish the executed version, so the probe reports the resolved
  package version separately and labels evidence from the executed CLI version.
- The pinned adapter reads `CODEX_PATH` and passes it to `startCodexConnection`. Without
  `CODEX_PATH`, it resolves the bundled `@openai/codex/bin/codex.js`.
- The adapter's `attachLogs` consumes Codex app-server stderr, while `Logger.log` drops
  it unless `APP_SERVER_LOGS` is configured. This is why adapter stderr alone cannot
  prove the malformed-role warning is absent.
- Codex `0.144.1` loads standalone agent-role TOML from configuration-layer `agents/`
  directories and emits the exact warning checked by the probe.
- Pinning the controls to `gpt-5.5` with `multi_agent=true` and
  `multi_agent_v2=false` selects stable V1 for this focused role-loading probe.
