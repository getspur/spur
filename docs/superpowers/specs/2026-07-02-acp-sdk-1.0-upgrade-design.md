# ACP SDK Upgrade 0.11.1 → 1.0.x — Design

**Date:** 2026-07-02
**Status:** Approved for planning
**Owner:** spur-acp (primary), spur-core / spur-tui / spur-bot (blast radius)

## Goal

Upgrade the workspace from `agent-client-protocol 0.11.1` (schema crate
`0.12.0`) to the upstream `1.0.x` line (schema crate `1.1.0+`), absorbing
five breaking-change releases (0.12 → 0.13 → 0.14 → 0.15 → 1.0) while:

1. keeping the `NativeAcpConnection` builder/handler wiring byte-compatible
   in behavior,
2. migrating the model-selection surface off the removed
   `unstable_session_model` API onto session config options, and
3. centralizing all upstream schema imports behind the `spur-acp` re-export
   shim so future SDK bumps are a one-file change.

## Non-goals

- Adopting the new `Stdio` transport / `AcpAgent` helper to replace SPUR's
  manual child-spawn + `tokio_util::compat` plumbing. Evaluated separately
  after the upgrade lands (see §9, PR-2 candidate).
- Adopting HTTP/WebSocket transports (`agent-client-protocol-http`, new in
  0.15). No SPUR use case yet.
- Enabling `unstable_protocol_v2`. Upstream deliberately keeps it out of the
  `unstable` umbrella; `ProtocolVersion::LATEST` remains V1.
- Any behavioral change to the review loop, TUI event draining, broadcast
  sizing, or ACP notification grace windows (established invariants).

## What survives unchanged (verified symbol-by-symbol)

The entire connection-layer contract `native.rs` builds on is intact on 1.0.x:

- `ByteStreams::new(out, in)` (`rust-sdk jsonrpc.rs:4413`), now implementing
  the new `ConnectTo` trait; SPUR's `tokio_util::compat` wrapping at
  `crates/spur-acp/src/connection/native.rs:1281-1283` still applies.
- `Client.builder().name(…).on_receive_request(op, on_receive_request!())
  … .on_receive_notification(…) .connect_with(transport, main_fn)` — same
  shapes including the `to_future_hack` macros and the `+ Send` handler
  bound (`Builder::on_receive_request` at `jsonrpc.rs:1033`,
  `Client::connect_with` at `role/acp.rs:65`).
- `ConnectionTo::{spawn, send_request, send_notification}` (plus new `*_to`
  routing variants SPUR doesn't need).
- `Error::internal_error()` / `Error::invalid_params()` with `.data(…)`;
  `Result` — now re-exported from `schema::v1` but path-stable at crate root.
- `ClientRequest::ExtMethodRequest` (schema v1 `agent.rs:4746`) — the ext-call
  wrapping at `native.rs:1971` keeps working.
- `AgentNotification::{SessionNotification, ExtNotification}` (schema v1
  `client.rs:2355-2390`).
- Every `SessionUpdate` variant SPUR matches (`UserMessageChunk`,
  `AgentMessageChunk`, `AgentThoughtChunk`, `ToolCall`, `ToolCallUpdate`);
  `UsageUpdate` is stable and field-identical (`used`/`size`/`cost`/`meta`).
- Terminal types, `McpServer`, `SessionModeState`, `SetSessionConfigOption*`,
  `SessionConfigSelect*` (plus new `SessionConfigSelectGroup`),
  `ProtocolVersion::LATEST`, and all `new()` constructors SPUR calls
  (`InitializeRequest/Response`, `NewSessionResponse`, `SessionId`, …).

## The three breaks

### B1 — Feature flags removed

`unstable_session_usage` and `unstable_session_model` no longer exist. The
schema 1.1.0 unstable set is: `unstable_auth_methods`,
`unstable_cancel_request`, `unstable_elicitation`, `unstable_llm_providers`,
`unstable_mcp_over_acp`, `unstable_nes`, `unstable_plan_operations`,
`unstable_session_fork`, `unstable_end_turn_token_usage`,
`unstable_boolean_config` (+ standalone `unstable_protocol_v2`). The build
fails at `cargo metadata` until `Cargo.toml:120` drops both features. Usage
was stabilized (0.14); the session-model API was **removed**, not stabilized
(see B3). No replacement feature is required for current behavior.

### B2 — Flat schema paths removed

`agent_client_protocol::schema::` now exposes only the `v1` (and gated `v2`)
submodules plus `ProtocolVersion`, `MaybeUndefined`, `IntoOption`,
`IntoMaybeUndefined` at the root (`rust-sdk schema/mod.rs:318-331`). Every
message type must come from `schema::v1::`.

Blast radius: 19 files in `crates/spur-acp` import
`agent_client_protocol::schema::` directly; 63 more `use` statements exist
across `spur-core`, `spur-tui`, `spur-bot`, and tests.

Mitigation: `crates/spur-acp/src/lib.rs:128-140` already re-exports ~50
schema types. The design point (§6) is to make that shim the **only** place
in the workspace that names upstream schema paths.

### B3 — Model-selection API removed

Schema 1.1.0 has **no** `SessionModelState`, `ModelInfo`, `ModelId`, or
`SetSessionModel{Request,Response}`, and `NewSessionResponse` lost its
`models` field (v1 fields: `session_id`, `modes`, `config_options`, `meta` —
schema v1 `agent.rs:994-1018`). Model choice is expressed through session
config options (`SessionConfigOption` with `Select` kind; grouped selects via
the new `SessionConfigSelectGroup`).

Affected SPUR surface:

| Site | Today | After |
|---|---|---|
| `SpurAgentCaps.models: Option<SessionModelState>` (`spur_agent_caps.rs:37`) | Snapshot of `NewSessionResponse.models` | Derived view over cached `config_options` where `config_id == "model"` |
| `SpurAgentCaps::supports_set_model()` (`spur_agent_caps.rs:87-95`) | non-empty `available_models` | non-empty choices on the `model` config option |
| `SpurAgentCaps::current_model_label()` (`spur_agent_caps.rs:113-121`) | resolve `current_model_id` in `available_models` | resolve `current_value` in `AdvertisedChoice` list |
| `decide_set_session_model_dispatch` (`native.rs:254-278`) | 3-way: `Direct` \| `FallbackConfigOption` \| `Unsupported` | 2-way: config-option \| unsupported (`Direct` arm deleted) |
| `AcpCommand::SetSessionModel` (`native.rs:158-160`) + `set_session_model` trait method (`connection/mod.rs:209`) | sends `session/set_model` | routes through `set_session_config_option` |
| `adapter/config_options.rs` | already synthesizes `AdvertisedCommand` for `model`/`reasoning_effort` via allow-list | becomes the single source of model metadata |

The structural luck: SPUR **already implements the fallback path**. The
`FallbackConfigOption` dispatch arm and the vendor-neutral
`AdvertisedCommand` synthesis exist and are tested. The migration is a
collapse (delete the `Direct` arm and the `SessionModelState` snapshot), not
a build-out.

## Design

### §1 — Dependency + feature bump

`Cargo.toml:120` becomes:

```toml
agent-client-protocol = { version = "1.0" }
```

No unstable features required. `unstable_cancel_request` is deliberately NOT
enabled in this upgrade (candidate for a follow-up; see §9).

### §2 — Single-shim import policy

`crates/spur-acp/src/lib.rs:128` changes its source path:

```rust
pub use agent_client_protocol::schema::v1::{ /* existing list + additions */ };
```

New workspace rule (enforced by review, optionally by a lint-invariants
check): **no crate other than `spur-acp` may name `agent_client_protocol`**.
All 63 external `use agent_client_protocol::schema::…` statements across
`spur-core`/`spur-tui`/`spur-bot` are rewritten to `use spur_acp::…`. Inside
`spur-acp`, the 19 files rewrite `schema::` → `schema::v1::` (mechanical).

Additions to the shim needed by existing code: `AgentCapabilities`,
`CancelNotification`, `ClientCapabilities`, `ContentBlock` internals already
present; audit against the full import inventory during implementation.

### §3 — Model surface migration

1. Delete `SpurAgentCaps.models` and its type. Replace with a derived
   accessor over the cached config options (the cache already exists for the
   M10.1 pickers):

   ```rust
   impl SpurAgentCaps {
       pub fn model_option(&self) -> Option<&SessionConfigOption> { /* config_id == "model" */ }
       pub fn supports_set_model(&self) -> bool { /* model_option has non-empty Select choices */ }
       pub fn current_model_label(&self) -> Option<String> { /* resolve current value's label */ }
   }
   ```

2. Delete `SetSessionModelDispatch::Direct` and the
   `AcpCommand::SetSessionModel` request plumbing; `set_session_model` on the
   `AgentConnection` trait keeps its signature (vendor-neutral strings) but
   is implemented as `set_session_config_option("model", value)`.

3. `extract_choices` (`adapter/config_options.rs:57`) gains a `Grouped` arm:
   1.x agents may advertise models via `SessionConfigSelectGroup`; v1
   flattening (group label folded into description) is sufficient.

4. Downstream (`spur-tui` session detail model picker, dashboard status
   line) consume `SpurAgentCaps` accessors only — signatures unchanged, so
   the TUI change is limited to whatever used `SessionModelState` fields
   directly (audit: `spur-tui/src/views/session_detail/*`, `app/mod.rs`).

### §4 — Serialization compatibility

`SpurEvent` persists `SessionNotification` payloads
(`domain/events.rs:12`). The v1 wire format is unchanged (same protocol
version), so recorded events deserialize identically; the round-trip suite
(`tests/executor_events_roundtrip.rs`) is the proof gate. New-schema
resilience (`DefaultOnError`, `VecSkipError` on `NewSessionResponse` and
list fields) is strictly more permissive — malformed agent output that
previously failed the whole response now degrades per-field. Defensive
tests in `tests/auto_approve_defensive.rs` must keep passing unchanged.

### §5 — Behavior deltas to absorb (not code changes)

- **1.0.1 ignores unhandled notifications.** Previously unknown
  notifications could surface errors. SPUR's quirk handling
  (`agent_quirks.rs`) assumed noisy agents needed tolerance — this now comes
  for free; no SPUR code depends on the error path (verified: no handler
  branches on unknown-notification errors).
- **Core crate no longer pulls `tokio`.** SPUR supplies its own tokio
  runtime (`native.rs:1081`); no change, but the lockfile shrinks
  (`jsonrpcmsg`, `rmcp` out of the `spur-acp` transitive graph).

## Testing

- TDD cadence per repo guidelines: failing `test(...)` commit before each
  `fix(...)`/`feat(...)` in PR-1.
- Gates: `scripts/spur-cargo test -p spur-acp` (config validation +
  round-trip), `scripts/spur-cargo test --workspace` before each PR merge,
  `SPUR_REMOTE=1 scripts/spur-cargo clippy --workspace -- -D warnings`.
- `examples/compat_spike.rs` and `examples/skip_perm_spike.rs` compile-check
  the client-side surface against real agents; re-run manually against
  codex-acp and claude-agent-acp before PR-1 merges.
- Round-trip suite `tests/executor_events_roundtrip.rs` is the serialization
  compatibility gate (§4).

## Risks & open questions

1. **Do current agents (codex-acp, claude-agent-acp, gemini) advertise a
   `model` config option on their 1.x-era builds?** The fallback dispatch
   assumed they might not (hence `Unsupported`). If an agent still only
   speaks the removed `session/set_model`, model switching silently degrades
   to unsupported for it. Mitigation: probe with `compat_spike` before PR-1;
   the wire probe test `tests/codex_0_12_wire_probe.rs` is the template.
2. **Schema 1.2.0 exists on crates.io** while rust-sdk `main` pins `=1.1.0`.
   Pin whatever the released 1.0.x resolves; do not float the schema crate
   independently.
3. **`ModelId` leaks into vendor-neutral types?** `connection/mod.rs:37`
   imports `ModelId` for the trait surface. PR-0 must swap it to a plain
   string (or a spur-local newtype) since the type no longer exists.
4. **Grouped selects** (`SessionConfigSelectGroup`) are new; v1 flattening
   (§3.3) may lose grouping UX. Acceptable for now; revisit if an agent
   ships grouped model lists.
