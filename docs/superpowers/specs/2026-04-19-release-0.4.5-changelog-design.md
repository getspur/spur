# Release 0.4.5 + Business-Value Changelog — Design

**Status:** approved 2026-04-19
**Author:** brainstorming session with user (Kevin Truong)
**Scope:** single release cut — version bump, changelog rewrite, tag push through the existing cargo-dist → npm pipeline.

## Purpose

Ship `0.4.5` with a public-facing changelog that communicates **what users can now do** rather than **what changed internally**. Establish reusable filter rules so subsequent releases (`0.4.6`, `0.5.0`) can be drafted the same way without re-brainstorming.

## Context

- **Last released tag:** `v0.4.1`.
- **Commits since last tag:** 367 (`git log v0.4.1..HEAD`).
- **Single version source of truth:** `Cargo.toml:16` (`[workspace.package] version`). All nine crates inherit.
- **Release pipeline:** `dist-workspace.toml` drives `cargo-dist 0.31.0`. Pushing a `vX.Y.Z` tag triggers `.github/workflows/release.yml` which cross-compiles six target triples, publishes `@getspur/spur@X.Y.Z` to npm, and creates a GitHub Release on the public `getspur/spur-releases` repo (source stays private on `getspur/spur`). The Release body is extracted from the matching `## vX.Y.Z` H2 in `CHANGELOG.md`.
- **No `package.json` to bump.** The npm installer is generated by cargo-dist from `Cargo.toml`.
- **Existing `## Unreleased` section** in `CHANGELOG.md` already documents the Brain delegation framework. It is incomplete — it does not cover palette, PickerShell unification, react_trace markdown/mermaid, skills installer, or the session-picker improvements shipped since `v0.4.1`.

## Decisions

### Decision 1 — Scope of release notes

Cover the **major user-facing themes** of `v0.4.1..HEAD` (4–8 themes). Do **not** exhaustively audit 367 commits; do **not** restrict to only the currently-curated `## Unreleased` section.

### Decision 2 — Audience & voice

Primary audience: existing spur users upgrading, developer-type. Secondary audience: prospective users reading the GitHub Release page. Deliver as:

- One short **benefit-first preamble** (≈3 sentences) so an evaluator gets the "what does this release do for me" in 10 seconds.
- Concrete **"you can now…"** bullets for upgraders.

No exec-summary / marketing-roll-up voice. No internal type names, phase numbers, or ticket references.

### Decision 3 — Delivery surface

**`CHANGELOG.md` only.** No parallel `docs/releases/vX.Y.Z.md`. Cargo-dist reads the changelog directly; a second file would drift.

### Decision 4 — Gated / experimental features

Dedicated **`### Preview features (opt-in)`** subsection. Required whenever a feature is merged but not default-on in release builds. Must include the exact config snippet a user needs to flip it on. 0.4.5 entry: Brain delegation framework (`[brain.delegation] framework = "v1"`, release-build default is `legacy`).

## Filter rules (reusable)

Apply these when converting commit log → changelog draft:

| Commit kind | Decision |
|---|---|
| `feat:` user can see/touch | **include** — rewrite as user benefit |
| `feat:` internal scaffold (e.g., "add SlashQuerySource") | **drop** |
| `fix:` user-visible regression | **include** |
| `fix:` internal / compile / clippy | **drop** |
| `perf:` perceivable (latency, smoothness) | **include as Improved** |
| `perf:` micro-optimization, no user signal | **drop** |
| `refactor:` / `style:` / `chore:` | **drop** |
| `test:` | **drop** |
| `docs(plan):` / `docs(spec):` | **drop** |
| Feature-flagged, not default-on in release build | **Preview features (opt-in)** with config snippet |
| Phase numbers, ticket refs, internal type names | **drop from copy** (may stay in commit titles) |

## Structure of each release entry

```
## vX.Y.Z — YYYY-MM-DD

<preamble: 2–3 sentences, benefit-first, names the 2–3 biggest themes>

### Added
<5–8 "You can now…" bullets — user-facing features>

### Improved
<3–5 bullets — perf and UX polish that a user would perceive>

### Fixed
<0–3 bullets — only notable user-visible fixes>

### Preview features (opt-in)
<gated features with required config snippet>
```

Omit any subsection that has no entries.

## 0.4.5 content outline (to be expanded into final copy)

**Preamble themes:** (1) a universal Ctrl+K palette for navigation, (2) unified mention/slash pickers, (3) richer in-trace content (markdown + mermaid), (4) smoother streaming.

**Added:** universal palette, unified `@mention`/`/slash`, Ctrl+R recent-session rerun, auto-resume landing, markdown + mermaid in traces, dashboard view, skills installer across five adapters, delegation plans surfaced in the timeline, richer worker descriptors.

**Improved:** streaming smoothness under bursty traffic, palette/picker rerank performance, session metadata persistence.

**Preview features (opt-in):** Brain delegation framework behind `[brain.delegation] framework = "v1"`.

## Execution steps

1. Bump `Cargo.toml:16` → `version = "0.4.5"`. Run `cargo check --workspace --all-targets` — must be clean.
2. Rewrite `CHANGELOG.md`: rename the current `## Unreleased` H2 to `## v0.4.5 — 2026-04-19`, replace its body with the structure above, insert a fresh empty `## Unreleased` H2 above it.
3. Commit both files together as `chore(release): 0.4.5`.
4. Tag the commit: `git tag -a v0.4.5 -m "Release v0.4.5"`.
5. Push: `git push origin main && git push origin v0.4.5`.
6. Confirm the release workflow on GitHub Actions; confirm `@getspur/spur@0.4.5` appears on npm; confirm the GitHub Release body on `getspur/spur-releases` matches the CHANGELOG section.

## Out of scope

- Migrating historical release notes (`v0.1.0`, `v0.3.0`, `v0.4.0`, `v0.4.1`) into the new structure.
- Marketing copy outside the repo (blog post, newsletter, social).
- Changes to `dist-workspace.toml` or any regeneration of `release.yml` via `cargo dist init`.
- Adding a second delivery surface (`docs/releases/`, release announcements repo, etc.).
